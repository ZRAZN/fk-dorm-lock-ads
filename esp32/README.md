# ESP32 刷卡开门

用一个 ESP32-C3 + RC522 做成「刷卡就开锁」的小盒子。刷卡 → 板子用蓝牙按协议开锁 → 门开。

成本约 **¥30**，不需要焊接（买「排针已焊」的板子和模块），不需要联网，不需要手机。

---

## 硬件清单

| 件 | 型号 | 参考价 |
|---|---|---|
| 主控 | ESP32-C3 SuperMini（4MB，**排针已焊**） | ¥10～20 |
| 读卡 | RC522 / MFRC-522（**排针已焊**） | ¥4～8 |
| 线 | 40P 杜邦线，**母对母**，20cm | ¥5 |
| 卡 | MIFARE Classic 1K（S50）空白卡 | ¥1～2/张 |

**关键：线和板的公母要对上。** 板子和模块是公针 → 用母对母线。买「焊好 8P 底座」那款是母座，插不上。

RC522 买套装通常会带一张 S50 卡和钥匙扣，先用那张测通再考虑多买。

## 接线

```
        RC522                    ESP32-C3 SuperMini
    ┌──────────┐              ┌──────────────────┐
    │ 3.3V   ●─┼──────────────┼─● 3V3            │
    │ GND    ●─┼──────────────┼─● G              │
    │ RST    ●─┼──────────────┼─● GPIO3          │
    │ SDA/CS ●─┼──────────────┼─● GPIO7          │
    │ SCK    ●─┼──────────────┼─● GPIO4          │
    │ MOSI   ●─┼──────────────┼─● GPIO6          │
    │ MISO   ●─┼──────────────┼─● GPIO5          │
    │ IRQ    ●─┼─── 悬空 ──────┼─               │
    └──────────┘              └──────────────────┘
```

- RC522 丝印（面对元件面，从左到右）：`SDA SCK MOSI MISO IRQ GND RST 3.3V`
- **3.3V 和 GND 不能接反**，接反会烧模块
- 剩下 5 根**必须按上表接**，固件不做引脚自动探测（试过，悬空脚噪声会被误判成成功）

> 早期版本试过 1680 种引脚排列自动探测，实测会被悬空脚噪声骗到（读出 `0xFD` 这种乱值），
> 所以改成写死 `SPI.begin(4, 5, 6, 7)`。接错就是 9 下快闪，按表重接即可。

## 烧录

### 1. 装工具链

```bash
arduino-cli core install esp32:esp32@2.0.17
arduino-cli lib install MFRC522      # 1.4.12
```

### 2. 改常量

打开 `cardreader.ino`，改开头这几行：

```cpp
static const char *LOCK_MAC = "AA:BB:CC:DD:EE:FF";                       // 你的门锁 MAC
static const char *ACTIVATION_KEY = "00000000000000000000000000000000";  // 你的 activationKey

// 卡内口令与扇区密钥：建议改成自己的随机值再编译
static const uint8_t PASS_KEY_A[6] = { 0x11, 0x22, 0x33, 0x44, 0x55, 0x66 };
static const uint8_t PASS_KEY_B[6] = { 0x77, 0x88, 0x99, 0xAA, 0xBB, 0xCC };
static const uint8_t PASS_TOKEN[16] = { /* 16 字节随机数 */ };
```

前两个怎么拿，见[主 README](../README.md)。

### 3. 编译

```bash
arduino-cli compile --fqbn "esp32:esp32:esp32c3:CDCOnBoot=cdc" .
```

`CDCOnBoot=cdc` 必须带，否则 USB 串口打不开。

### 4. 烧录

`arduino-cli upload` 在部分 USB-Serial/JTAG 板子上会报 `No serial data received`。
这种情况改用 esptool 直接写 app 分区：

```bash
arduino-cli compile --fqbn "esp32:esp32:esp32c3:CDCOnBoot=cdc" --output-dir build_out .
python -m esptool --chip esp32c3 -p COM5 -b 460800 \
    --before default_reset --after hard_reset \
    write_flash 0x10000 build_out/cardreader.ino.bin
```

bootloader 和分区表沿用板上原有的，不用重写。

### 5. 看串口

```python
import serial, time
s = serial.Serial("COM5", 115200, timeout=0.2)
s.dtr = False      # 关键：打开前把 DTR/RTS 拉低，否则会触发复位，读到 0 字节
s.rts = False
s.open()
while True:
    line = s.readline()
    if line:
        print(line.decode("utf-8", "replace").rstrip())
```

## 灯语

板载 LED 在 `GPIO8`，**低电平点亮**。

### 开机

| 灯 | 含义 |
|---|---|
| 2 下慢闪（600ms） | RC522 认到了，正常 |
| 9 下快闪（90ms） | 读不到 RC522：接线错 / 供电没有 / 模块坏 |

固件启动时会重试读版本寄存器 12 次（每次间隔 250ms），因为 RC522 上电比 ESP32 慢。

> 国产兼容芯片（CV520 之类）返回的版本号是 **0x82**，不是原厂的 0x92。
> 判定逻辑是「非 0x00 且非 0xFF 即成功」，两种芯片都认。

### 刷卡

| 灯 | 含义 |
|---|---|
| 6 下快闪（90ms） | **开锁成功** |
| 4 下快闪（90ms） | 锁回了拒绝（卡没权限/锁状态不对） |
| 4 下中闪（250ms） | 蓝牙连不上（锁不在范围 / 被别的设备占着） |
| 5 下快闪（90ms） | 扇区认证失败：这张卡没写过口令，或是克隆卡 |
| 7 下快闪（90ms） | 认证过了但口令不对 |
| 3 下长闪（500ms） | 卡在黑名单，或不在白名单 |

### 写卡

| 灯 | 含义 |
|---|---|
| 5 下快闪 | 进入写卡模式 |
| 2 下慢闪（600ms） | 写成功一张 |
| 4 下中闪（300ms） | 写失败（卡被锁 / 不是空白 S50） |
| 结束：2 下慢闪 | 写卡模式结束，至少写成功一张 |
| 结束：7 下慢闪 | 写卡模式结束，一张都没写 |

## 速度

| 场景 | 耗时 |
|---|---|
| 冷启动第一次刷卡 | 5～7 秒（其中约 5 秒是 BLE 连接 + 服务发现 SDP） |
| 60 秒内再刷 | 0.7～2 秒（复用连接） |
| 超过 60 秒 | 自动断开，把门锁的 BLE 通道让出去 |

首次慢是 ESP32 蓝牙协议栈做 SDP 的固有开销，改不了。开锁成功后固件会**保持连接 60 秒**，
这段时间内连刷是秒开；60 秒后主动 `disconnect`，因为门锁通常只允许一个 BLE 连接，
一直占着室友的手机就连不上了。

协议本身还有一段 **180ms 的固定等待**（建链 ack 之后才能发开锁帧），这个不能省，官方客户端也一样。

## 写卡（给卡加口令，防克隆）

出厂的空白 S50 卡谁都能复制 UID。写一次口令之后，只有知道口令的读卡器才能验通过。

**不需要电脑**，按住板子上的 BOOT 键就行：

```
按住 BOOT 2.5 秒     → 闪 5 下，进入写卡模式
贴第一张卡           → 闪 2 下慢 = 写好
拿开，贴第二张       → 再闪 2 下慢
...
60 秒后自动退出      → 写成功过闪 2 下慢，一张没写闪 7 下慢
```

写进去的东西：

| 位置 | 内容 |
|---|---|
| 块 4（扇区 1 数据块） | 16 字节口令 `PASS_TOKEN` |
| 块 7（扇区 1 尾块） | `KeyA(6) + FF0780 + KeyB(6)` |

> 块 7 顺序不能错，写错这个扇区就废了。**写完之后出厂密钥 `FFFFFFFFFFFF` 就失效了**，
> 这张卡从此只有本固件能读——想重写只能换新卡。

### 卡丢了怎么办

把丢的那张卡的 UID 填进黑名单，重烧一次：

```cpp
static const char *DENY_UID[] = {
  "11223344",     // 丢掉的那张
};
```

其它卡不用重写，照常用。

### 白名单

`ALLOW_UID[]` 为空时表示「所有持有效口令的卡都放行」。要收紧就把 UID 填进去：

```cpp
static const char *ALLOW_UID[] = {
  "A1B2C3D4",
  "11223344",
};
```

UID 可以从串口日志 `card: XXXXXXXX` 里抄。

## 安全边界

这套东西的安全强度，从弱到强：

| 措施 | 挡住什么 |
|---|---|
| 设备放在宿舍里 | 陌生人得先走到你门口 |
| UID 白名单 | 随手拿张卡乱刷 |
| 卡内口令 + 自定义扇区密钥 | 手机 NFC 克隆、市面上几块钱的 UID 卡 |
| 改掉源码里的默认口令/密钥 | 别人拿源码自己造一张同款卡 |

**挡不住的**：Proxmark3 或 mfoc 这类工具能把 MIFARE Classic 完整破解克隆。这属于需要专用设备、拆开你的卡读十几分钟的攻击，成本远高于收益。

**真正的钥匙其实是 `activationKey`**——它在固件里，没有它做不出能开你门的东西。

## 省电（可选）

想用电池供电，需要改固件：

- 空闲时 `esp_deep_sleep_start()`，RC522 拉低 RST 进软断电（<80µA）
- 定时唤醒（比如每 0.5 秒）读一次卡，没卡立刻睡回去
- 平均电流约 4～5mA
- 2000mAh 电池约 **2.5 周**，4000mAh 约 **5 周**

不省电的话常开是 60～90mA，2000mAh 只能撑 1～2 天，没意义。

> 注意：深度睡眠会丢掉 BLE 连接，每次唤醒都要重连，
> 那就退化成「每次刷卡 5～7 秒」。省电和速度只能二选一。

## 排障

| 现象 | 原因 |
|---|---|
| 9 下快闪 | RC522 没供电 / 模块坏 / SPI 线松。先推一推排针看有没有虚焊 |
| 串口出现 `version now 0x00` | 同上；也可能是 RC522 上电太慢，多等 2 秒再按复位 |
| 3 下长闪，不开锁 | 卡不在白名单，或在黑名单 |
| 5 下快闪 | 扇区认证失败：这张卡没写过口令，或者用的是出厂默认密钥而固件已经改成自定义的 |
| 7 下快闪 | 口令不匹配：这张卡是别的固件写的 |
| 4 下中闪 | 蓝牙连不上：门锁不在 3 米内，或被手机 App 占着连接 |
| 贴卡后要等十几秒才有反应 | 老版本问题，现在已修（原因是 `PICC_HaltA` 让卡不再应答 REQA） |
| 认证偶尔失败 `auth fail` | 选卡和认证之间不能插任何延时/闪灯，卡会被晾到超时 |
| 写卡闪 4 下 | 卡被锁了（校园卡、门禁卡通常写不进去），换空白 S50 |
| 烧录报 `No serial data received` | 用 esptool 直接写 `0x10000`，见上文 |
| 插上电脑认不到串口 | 换数据线（很多线只有充电针），或重启电脑复位 USB 栈 |
| 打开串口读到 0 字节 | 打开前没设 `dtr=False; rts=False`，触发了 USB-JTAG 复位 |
